# Got You Covered (GYC)

Bare React Native app (no Expo). The `android/` project is hand-maintained and tracked in git — it is not regenerated by any CLI step.

## Android development

Install Node.js, Android Studio with the Android SDK and an emulator image that includes Google Play, and JDK 17. On this Windows machine, JDK 17 is installed at the path below.

The C: drive on this machine runs close to full, which starves the pre-installed emulators (`~/.android/avd`) and the default Gradle/npm caches (`~/.gradle`, `~/AppData/.../npm-cache`) of scratch space and causes hangs or "not enough disk space" failures. This repo instead keeps a dedicated AVD on D: inside the project folder, and the Gradle cache at `D:\.grhome` (**not** inside the project folder — React Native's native (C++/CMake/ninja) build generates deeply nested header paths that exceed Windows' 260-character path limit once combined with a long `GRADLE_USER_HOME`; even with registry long-path support enabled, `ninja` does not honor it on Windows). Always set these env vars before touching Android tooling here:

```powershell
$env:JAVA_HOME = Join-Path $env:USERPROFILE '.gradle\jdks\eclipse_adoptium-17-amd64-windows.2'
$env:GRADLE_USER_HOME = 'D:\.grhome'
$env:ANDROID_AVD_HOME = Join-Path (Get-Location) '.android-emulator-home\avd'
$env:ANDROID_SDK_HOME = Join-Path (Get-Location) '.android-emulator-home'
$env:ANDROID_EMULATOR_HOME = Join-Path (Get-Location) '.android-emulator-home'
Copy-Item .env.example .env # only on a fresh checkout; fill in Firebase values
npm ci --cache (Join-Path (Get-Location) '.npm-cache')
emulator -list-avds        # should show MechIntel_API_35
emulator -avd MechIntel_API_35
```

`MechIntel_API_35` is a project-local AVD (Android 35, Google Play) whose data lives under `.android-emulator-data/` on D:, so it does not compete with the pre-installed `Medium_Phone_API_35` / `pixel_7_-_api_35` emulators on C:. The first boot needs a Google account signed in via Settings once the emulator is up (required for Google Sign-In).

In a second terminal, from the repo root, set the same `JAVA_HOME`/`GRADLE_USER_HOME` and then:

```powershell
$env:ORG_GRADLE_PROJECT_reactNativeArchitectures = 'x86_64' # emulator-only debug APK
npm run android
```

`npm run android` (`react-native run-android`) compiles a debug APK from the tracked `android/` project with Gradle, installs it on the running emulator, and starts Metro. For later JavaScript-only changes, `npm start` is enough. Rebuild with `npm run android` after native dependency changes (new native module, Gradle/manifest edits).

On this machine, a clean build with all four Android ABIs exceeded the paging limit. For the first emulator build, stop the emulator temporarily and build one ABI with one Gradle worker:

```powershell
$env:ORG_GRADLE_PROJECT_reactNativeArchitectures = 'x86_64'
Set-Location android
.\gradlew.bat :app:assembleDebug --max-workers=1 --gradle-user-home $env:GRADLE_USER_HOME
Set-Location ..
```

Then start the emulator and run `npm run android`. Clear `ORG_GRADLE_PROJECT_reactNativeArchitectures` when building for other Android devices.

Custom fonts (Inter, Plus Jakarta Sans) live in `src/assets/fonts/` and are statically linked via `react-native.config.js`. After `npm install` on a fresh checkout, or after adding/removing a font file, run `npx react-native-asset` and rebuild with `npm run android` — this copies the `.ttf` files into `android/app/src/main/assets/fonts/`.

If a Gradle build hangs with no output for several minutes, a stale daemon from a previous low-disk-space failure is usually the cause. Delete `$env:GRADLE_USER_HOME\daemon` and rerun with `--no-daemon` once to clear it:

```powershell
Remove-Item -Recurse -Force (Join-Path $env:GRADLE_USER_HOME 'daemon')
Set-Location android
.\gradlew.bat <task> --no-daemon --gradle-user-home $env:GRADLE_USER_HOME
Set-Location ..
```

## Google sign-in setup

The Android package name is `com.mechatron.mechintel`. Use this exact name when registering the Android app in the Firebase project. Enable Google under Firebase Authentication > Sign-in method. Register the debug signing certificate SHA-1 in Firebase Project settings > Your apps > Android app. Get the fingerprint with:

```powershell
Set-Location android
.\gradlew.bat signingReport --gradle-user-home $env:GRADLE_USER_HOME
Set-Location ..
```

The current debug keystore (`~/.android/debug.keystore`, shared across all RN/Android projects on this machine) fingerprints as:

```
SHA1:   E7:51:DA:02:BE:4F:C5:7F:88:0F:2E:EB:0B:E5:65:93:86:20:4C:F9
SHA256: 8B:2E:4A:25:1F:A6:69:9E:8D:82:A0:FF:86:DA:D8:76:B0:F8:CD:61:D1:BF:48:EF:2B:57:DA:9D:31:FD:5E:F9
```

Register the SHA1 value in Firebase, not the SHA256. If the debug keystore is ever regenerated, rerun `signingReport` — the fingerprint above will no longer match.

In the same Firebase/Google Cloud project, obtain the OAuth client ID of type **Web application** and set `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` in the ignored `.env` (the `EXPO_PUBLIC_` variable name prefix is kept only for continuity with existing `.env` files — it has no special meaning now; `.env` values are inlined at build time by the `react-native-dotenv` babel plugin, see `babel.config.js`). The Android OAuth client is associated with the package name and SHA-1 in Google Cloud; its ID is not entered in the app. After changing `.env`, restart Metro with cache reset (`npm start -- --reset-cache`) since inlined env values are baked in at bundle time. Use an emulator with Google Play services and a signed-in Google account.

Google sign-in uses the native account picker, then exchanges the Google ID token for a Firebase credential. Email and password sign-in uses Firebase directly. The Firebase project values in `.env` are required for either method. `google-services.json` is not consumed by this app's Firebase JavaScript SDK; never put service account JSON in the mobile app.
